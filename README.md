# SaveMOD — Telegram Business Constructor + Module (FIXED build)

Production-ready Telegram-бот на **Node.js + grammY** в духе SaveMOD:
бот-конструктор управляемых ботов (Bot API 9.6 «Managed Bots», апрель 2026) +
универсальный бизнес-модуль с точечными командами и сохранением исчезающих
медиа.

> Версия: Bot API 10.0 (8 мая 2026)

## Состав

| Файл              | Назначение |
| ----------------- | ---------- |
| `constructor.js`  | Бот-конструктор. Inline-меню «Мои боты», автоматическое создание через `t.me/newbot/...`, авто-привязка токена через `getManagedBotToken`, авто-запуск `module.js`, админ-панель, рассылки, премиум через Stars. |
| `module.js`       | Универсальный модуль, прикручиваемый к **любому** созданному боту. Reply-edit UI, anti-delete/anti-edit, сохранение исчезающего, точечные команды, авто-очистка медиа по TTL. |
| `.env`            | Переменные окружения. |

## Что было сломано и что исправлено

### 1. ❌ `401 Unauthorized` при запуске модуля (ГЛАВНАЯ ПРИЧИНА КРАША)

**Симптом из логов:**
```
[mod:SavedsdBot][ERR] GrammyError: Call to 'getMe' failed! (401: Unauthorized)
[mod:SavedsdBot] exited code=1 sig=null
[mod:SavedsdBot] auto-restart in 5s…
```

**Причина.** В `constructor.js` было:
```js
const res = await ctx.api.getManagedBotToken(botUser.id); // ❌ голое число
```

grammY автоматически оборачивает все методы Bot API так, что **первый
аргумент — это объект-payload**. Передача голого `number` приводит к тому,
что либо метод не существует в типах (он добавлен в Bot API 9.6 — апрель
2026), либо вызов уходит с пустым payload и Telegram возвращает мусор. В БД
писалось `undefined`/невалидная строка, модуль стартовал с битым токеном,
`getMe` падал 401, процесс умирал, конструктор бесконечно перезапускал его.

**Исправлено.** Используем `bot.api.raw` (всегда работает через прокси, даже
для незадокументированных в типах методов) + правильный payload:
```js
async function callGetManagedBotToken(api, userId) {
  return api.raw.getManagedBotToken({ user_id: userId });
}
```
Плюс единый парсер ответа `extractToken(res)` — Telegram может вернуть
строку либо обёртку `{ token: "…" }`, в зависимости от версии grammY.

### 2. ❌ Бесконечный авторестарт убитого модуля

**Причина.** `child.on('exit')` перезапускал процесс при любом ненулевом
коде выхода — а 401 это «токен битый», лечится только новым токеном, а не
рестартом.

**Исправлено.** Анализируется stderr дочернего процесса; если там есть
`401: Unauthorized` — токен в БД зачищается (`UPDATE bots SET token = NULL`),
владельцу шлётся сообщение с кнопкой «🔁 Запросить токен», авторестарт
прекращается. Для прочих падений — экспоненциальный backoff с лимитом 5
попыток за 5 минут.

### 3. ❌ Нет валидации токена ДО записи в БД и спавна модуля

**Причина.** Если `getManagedBotToken` вернул мусор/строку без формата
токена, она сразу шла в БД и в `spawn module.js`.

**Исправлено.** Перед записью в БД:
1. `extractToken` проверяет регулярку `/^\d{6,}:[A-Za-z0-9_-]{30,}$/`;
2. `verifyToken(token)` делает `new Bot(token).api.getMe()`;
3. Только после двух успешных проверок токен сохраняется и модуль
   спавнится.

### 4. ❌ Модуль не работал в чатах (точечные команды молчали)

**Причина.** В `module.js` было несколько проблем:

- **`startReply` всегда слал через `business_connection_id`**, даже если
  владелец не разрешил боту `can_reply` в настройках Telegram Business.
  Запрос падал с `BUSINESS_PEER_INVALID` / `BUSINESS_CONNECTION_DISABLED`,
  и пользователь видел только тишину.
- **`updateMsgSavedPath.run`** вызывался с перепутанным порядком аргументов
  (`saved_path` стоял после ключей — а в подготовленном SQL он первый), и
  ничего не обновлялось.
- **`isFromOwner`** определялся через нечёткое сравнение, что иногда
  ломалось.

**Исправлено.**
- `startReply` теперь принимает `conn` и **сам решает**: если `can_reply`
  есть — отвечает в business-чате через `business_connection_id`; если
  нет — отвечает в ЛС с владельцем (`conn.user_chat_id`). Молчания больше
  не будет.
- При установке нового подключения владельцу присылается список реальных
  прав (что бот реально может делать), чтобы не было сюрпризов.
- `updateMsgSavedPath` — правильный порядок: SET-значение первое.
- `isFromOwner = m.from?.id === conn.user_id` — однозначно.

### 5. ❌ `.ttt` (крестики-нолики) не работали в business-чате

**Причина.** Telegram **не отображает inline-keyboard в business-сообщениях**
(известное ограничение API). Игра шла в business-чат и кнопки были
невидимы.

**Исправлено.** Команда `.ttt` теперь:
1. Шлёт в business-чате короткое уведомление со ссылкой на ЛС с ботом;
2. Саму игру (с рабочими кнопками) разворачивает в ЛС владельца.

### 6. ❌ Битый стартовый стек 401

**Причина.** В `module.js` `bot.start()` вызывался без try/catch, и при
битом токене Node.js выкидывал нечитаемый стек grammY.

**Исправлено.** Добавлен `main()` с предварительным `getMe()`. При 401
модуль выводит читаемое сообщение и завершается с кодом `3`, а stderr
content помогает конструктору отличить «токен битый» от «временная сеть».

### 7. Прочие чистки

- Удалены битые символы в текстах и комментариях.
- Удалены устаревшие fallback-ветки, которые путали логику.
- `pre_checkout_query` всегда отвечает `true` (как у вас и было).
- `MarkdownV2` в `cmdMute` корректно экранирует `can_delete_all_messages`.
- Добавлено сообщение при подключении со списком фактических прав бота.
- Сделан backoff авторестарта в конструкторе вместо безусловного `setTimeout 5s`.

## Запуск

```bash
npm install grammy better-sqlite3 dotenv
cp .env.example .env  # заполни переменные ниже
node constructor.js
```


## Поток данных (Bot API 9.6 → 10.0)

1. Пользователь жмёт **«✨ Создать бота»** → конструктор шлёт ссылку
   `https://t.me/newbot/{manager_username}/{suggested_username}?name={name}`.
2. Клиент Telegram открывает системное окно создания бота.
3. После подтверждения Telegram присылает **конструктору** два апдейта:
   - `Update.managed_bot` → `ManagedBotUpdated { user, bot }`
   - `Message.managed_bot_created` (в чате с конструктором)
4. ⚠️ Токена в апдейте **нет**. Запрашиваем отдельно:
   ```js
   api.raw.getManagedBotToken({ user_id: <bot.id> })
   ```
5. Валидируем токен (`getMe`), пишем в БД, спавним `module.js` как
   дочерний процесс.
6. Пользователь подключает нового бота в **Telegram Business** (Настройки
   → Чат-боты → выбрать бота). Прилетает `business_connection` с правами —
   модуль их сохраняет.

## Ограничения Bot API, о которых стоит знать

- **Inline-кнопки в business-сообщениях НЕ работают.** Для игровых
  команд (`.ttt`) и других интерактивных кнопок — отправка идёт в ЛС с
  ботом.
- **Без `can_reply` бот не сможет отвечать в чатах.** В этом случае
  модуль пишет владельцу в ЛС вместо business-чата. Чтобы получить
  полноценный UX, в Telegram → Настройки → Чат-боты → выбранный бот →
  «Разрешить отвечать на сообщения».
- **Удаление сообщений** работает только если выдано
  `can_delete_all_messages` (по умолчанию выключено).
